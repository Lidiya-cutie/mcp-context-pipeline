# DS-747/748: Эксперименты с LLM, промптами и производительностью кода

## DS-747 — Стабильность LLM и системных промптов

**Модель:** glm-4.7 (z.ai), mimo-v2.5 (OpenRouter — 404, endpoint недоступен)
**Запросы:** 3 EN queries × 5 системных промптов × 2 повтора = 60 прогонов (glm), 60 ошибок (mimo)
**Метод:** для каждой пары (модель, промпт) выполняется N повторов одного запроса, измеряется variance F1 и latency

### Результаты glm-4.7

| Промпт | avg F1 | stability | avg latency | errors |
|--------|--------|-----------|-------------|--------|
| neutral | 0.1667 | -1.4487* | 10875ms | 0% |
| expert | 0.0000 | 1.0000* | 32302ms | 0% |
| strict | 0.0000 | 1.0000* | 12452ms | 0% |
| ru-expert | 0.0000 | 1.0000* | 22060ms | 0% |
| safety | 0.0000 | 1.0000* | 18351ms | 0% |

*stability = 1 - (f1_stdev / avg_f1). При avg_f1=0 → артефакт. Реальная стабильность по latency: stdev neutral = 2341ms.

### Ключевые выводы DS-747

1. **glm-4.7 стабильно отвечает** (0% ошибок), но F1=0 на keyword-overlap — ответы развёрнутые, не совпадают с must_include keywords напрямую
2. **neutral промпт** даёт более быстрые ответы (10.9s) против expert (32.3s) — expert-промпт провоцирует более длинные ответы
3. **strict промпт** — самый быстрый после neutral (12.5s), но F1=0 (как и у остальных)
4. **mimo-v2.5** — endpoint OpenRouter изменился (404 на /v1/chat/completions), требуется обновить URL
5. **Latency variance** — значительная: от 10.9s до 32.3s в зависимости от промпта. Expert-промпт увеличивает latency в 3 раза
6. **ru-expert vs expert** — русскоязычный промпт быстрее (22s vs 32s), но F1 одинаковый

### Рекомендации

- Использовать **neutral** или **strict** промпты для продакшена (минимальная latency)
- Expert-промпты использовать только когда нужна глубина ответа
- Обновить endpoint mimo-v2.5 (проверить актуальный URL на OpenRouter)
- Для метрики качества использовать semantic similarity вместо keyword overlap (F1 на keywords нерепрезентативен для развёрнутых ответов)

## DS-748 — Производительность сгенерированного кода

**Модель:** glm-4.7 с system prompt "code generation system"
**Запросы:** 8 queries с expected_answer_type=code
**Метод:** генерация → subprocess с лимитами (10s CPU, 256MB RAM) → измерение

### Результаты

| Метрика | Значение |
|---------|----------|
| Сгенерировано | 8/8 (100%) |
| Исполнилось (exit=0) | 1/8 (12.5%) |
| Корректность (keywords) | 0/8 (0%) |
| Avg execution time | 838ms (единственный успешный) |
| Avg memory peak | 39.5 MB |
| Avg code size | 5931 bytes |
| Avg complexity (lines) | 120.6 |
| Avg complexity (branches) | 15.8 |

### Причины ошибок

| Запрос | Причина | Категория |
|--------|---------|-----------|
| CH-RU-001 | ModuleNotFoundError: clickhouse_connect | dependency |
| API-RU-008 | SyntaxError: invalid syntax | generation |
| PREF-EN-013 | ModuleNotFoundError: prefect | dependency |
| MCP-EN-019 | IndentationError | generation |
| LLM-RU-020 | ModuleNotFoundError: vllm | dependency |
| PGV-EN-025 | SyntaxError: unterminated string | generation |
| PREF-EN-026 | ModuleNotFoundError: prefect | dependency |
| MCP-EN-032 | **OK** (exit=0) | success |

### Категоризация ошибок
- **Dependency errors** (4/7 = 57%): код требует библиотеки, не установлённые в sandbox
- **Generation errors** (3/7 = 43%): синтаксические ошибки в сгенерированном коде (IndentationError, SyntaxError)
- **Correct execution** (1/8 = 12.5%): только MCP-EN-032 выполнилась без ошибок

### Ключевые выводы DS-748

1. **Execution rate = 12.5%** — только 1 из 8 программ исполнился. Основная причина — dependency errors (библиотеки не в sandbox)
2. **Generation quality** — 3 из 8 имеют синтаксические ошибки. Средний размер кода ~6KB, сложность ~120 строк / 16 ветвей
3. **Производительность** — единственный успешный прогон: 838ms, 39.5MB. Нормальные показатели для Python
4. **Методология**: для корректного бенчмарка нужен Docker-образ с предустановленными библиотеками (clickhouse-connect, prefect, vllm)

### Рекомендации

- Создать Docker sandbox с топ-10 библиотеками (из eval_queries)
- Добавить static analysis (pyflakes) перед execution — отлавливать SyntaxError без запуска
- Метрика correctness: проверять структуру кода (AST), не только keywords в выводе
- Включить timeout error как отдельную категорию (не смешивать с syntax/dependency)
